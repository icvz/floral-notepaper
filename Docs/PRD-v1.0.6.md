## 2. 用户故事

### 故事 1：修复多行引用 Bug（P0）

> As a **写作者**，I want **使用标准 Markdown 多行引用语法** so that **我能正确排版引用段落，包括多段落引用和嵌套引用**。

**场景**：

1. 用户在编辑器中输入多行引用（每行以 `>` 开头），期望每行在预览中独立显示为引用行
2. 用户创建多段落引用（段落间有空 `>` 行），期望预览中渲染为同一引用块内的两个段落
3. 用户在引用内嵌套其他元素（列表、标题），期望正确渲染

**当前问题分析**：

- `react-markdown` + `remark-gfm` 按 CommonMark 规范解析引用 —— 连续的 `>` 行被视为同一段落，软换行被合并
- `MarkdownPreview.tsx` 中的 `blockquote` 自定义组件（line 103-107）仅为样式包装，不做内容处理
- `MainWindow.tsx` 中 `quote` 格式化动作（line 212-228）正确插入 `> ` 前缀，编辑器侧无 Bug
- **根因**：CommonMark 规范下 `> line1\n> line2` 渲染为单一段落（line1 line2 用空格连接），用户期望每行独立

**修复方向**：

- 方案 A（推荐）：为 `blockquote` 内段落配置 `white-space: pre-line` 保留换行，同时在解析层插入 `<br>` 或修改 remark 插件行为
- 方案 B：自定义 `blockquote` 组件，解析 children 结构以支持每行独立渲染
- 额外需验证多段落引用（`> para1\n>\n> para2`）和嵌套引用（`>>`）是否正常工作

### 故事 2：Markdown 标准语法审查（P1）

> As a **用户**，I want **花笺支持 markdown.com.cn 定义的全部标准语法** so that **我的 Markdown 写作不受限制，预览与标准一致**。

**场景**：

1. 用户使用两空格换行（`  \n`）期望在预览中看到换行效果
2. 用户使用缩进四空格代码块，期望正确高亮
3. 用户粘贴自动链接（URL），期望自动转换为可点击链接

### 故事 3：阅读模式 / 编辑模式切换（P0）

> As a **阅读者**，I want **一键切换到纯净阅读模式** so that **我能不被编辑工具栏干扰，享受沉浸式阅读体验**。

**场景**：

1. 用户在编辑模式下写完笔记，按 Ctrl+E，编辑器切换为只读的 Markdown 渲染视图，右侧预览面板自动关闭，预览切换按钮隐藏
2. 用户在阅读模式下再按 Ctrl+E，平滑切换回编辑模式，恢复之前的编辑器状态和面板配置
3. 用户在阅读模式下仍能正常浏览和切换笔记

## 4. UI 交互说明

### 4.1 阅读/编辑模式切换

```
┌────────────────────────────────────────────┐
│  花笺 — 笔记标题        [便签] [—][□][×]  │  ← 标题栏
├────────────────────────────────────────────┤
│ [新建] [搜索...]           [阅读|编辑] [-]  │  ← 工具栏区域
│────────────────────────────────────────────│
│  笔记列表  │   标题输入框                  │
│  ├ 分类1   │   时间 · 字数 · 保存状态      │
│  │ ├ 笔记A │───────────────────────────────│
│  │ └ 笔记B │  [B][I][H][—][•][1.][<>][❝]  │  ← 格式化工具栏
│  └ 分类2   │                               │
│            │   编辑区 / 阅读区              │  ← textarea 或 MarkdownPreview
│            │                               │
│            │                               │
├────────────┴───────────────────────────────┤
│  Ln 42 | Markdown + LaTeX  |  UTF-8 | 12KB │  ← 状态栏
└────────────────────────────────────────────┘
```

**交互细节：**

1. **模式切换按钮**：位于工具栏右侧（SlidingButtonGroup 旁边），显示当前模式图标
   - 编辑模式：显示 ✏️ 图标 + "编辑" 文字
   - 阅读模式：显示 📖 图标 + "阅读" 文字
   - 点击切换，带 tooltip 提示 "阅读模式 (Ctrl+E)" / "编辑模式 (Ctrl+E)"

2. **阅读模式下的 UI 变化**：
   - 格式化工具栏（B/I/H/—/•/1./<>/❝/∑/∫）**隐藏**
   - 视图模式切换器（编辑/分栏/预览 SlidingButtonGroup）**隐藏**
   - textarea 替换为 MarkdownPreview 组件（只读渲染）
   - 标题 input 保留但设为 `readOnly`
   - 笔记列表侧栏保持不变（可正常切换笔记）

3. **快捷键 Ctrl+E**：
   - 在任何位置按下均触发热切换
   - 若当前无选中笔记，忽略（无效果）
   - 不可与其他快捷键冲突

4. **切换动画**：
   - 编辑器/阅读区使用 `animate-view-fade`（复用现有动画类）
   - 工具栏使用 CSS `transition` 渐变消失/出现
   - 目标切换耗时 < 200ms

5. **模式状态**：
   - 记入 `AppConfig.readModeDefault: boolean`，启动时恢复
   - 切换笔记时保持当前模式不变

### 4.2 现有 ViewMode 与新 readingMode 的关系

```
readingMode = false (编辑模式)     readingMode = true (阅读模式)
├── edit    → 纯编辑器              ├── (忽略 viewMode)
├── split   → 编辑器 + 预览面板     │   编辑器区 → MarkdownPreview (只读)
└── preview → 纯预览面板            │   预览面板 → 强制关闭
                                    │   视图切换器 → 隐藏
```

**核心规则**：`readingMode` 优先级高于 `viewMode`。进入阅读模式时保存当前 `viewMode`，退出时恢复。
